How this works

  • Build in your dev org (ApexPracticeOrg), never at work.
  • The live library stays on Supabase. This is a practice copy, so nothing here can break the real site.
  • Go in order. Each phase uses what the one before it built.
  • Each step says what you’re practicing and when it counts as done. How you build it is up to you.
00

Plan it and set up

Map what exists today and get your dev org ready.

1 · Inventory the current site
FoundationPlanning

List every screen and every Supabase table the library uses today, and decide which ones you'll rebuild. Start small: Links + Categories and the To-Do board are the core; the Deployment Tracker is the big one.

Done when

You have a written list: each screen → the table behind it → the Salesforce object it will become.

2 · Connect VS Code to the dev org
FoundationSFDXCLI

Work in ~/repos/ApexPracticeOrg. Confirm the org is authorized and set as the default.

sf org display -o ApexPracticeOrg
sf config set target-org ApexPracticeOrg
Done when

sf org open opens your dev org, and a test deploy of one tiny class succeeds.

3 · Pick the app shell
FoundationLightning App BuilderExperience Cloud

Decide where the library will live: a Lightning App inside Salesforce (for you, logged in) or an Experience Cloud site (a real web page, can be shared). Start with a Lightning App; the site is a stretch goal in phase 05.

Done when

A Lightning App called Resource Library exists with an empty Home page.

01

Build the data model

Turn each Supabase table into a custom object.

4 · Category and Link objects
FoundationCustom objectsLookup

Create Library_Category__c (Name, Color) and Library_Link__c (Title, URL, Description, Type picklist Work/Personal, lookup to Category).

Done when

You can create a Category and a Link in the UI, and the Link shows its Category.

5 · To-Do object
FoundationPicklistsNumber fields

Library_Todo__c: Title, Note, Status (Open / In progress / Done), Priority (0–3), Position (number, for drag order), Focused checkbox.

Done when

The fields match what the to-do board needs today.

6 · Deployment Tracker objects
WorkingMaster-detailCheckbox fields

Library_Deployment__c with a Stage picklist (Building → Sandbox → Deploying to Prod → Deployed to Prod → Verified), the flag checkboxes (PR created, PR approved, CR created, Test plan attached, CR approved), URLs and Blocked + reason. Add a lookup from To-Do to Deployment for the post-deploy steps.

Done when

A Deployment record can hold its checklist of linked To-Dos in a related list.

7 · Docs, Ideas, Learning, Scratch Pad
FoundationCustom objectsFiles

Objects for Documents (title, URL, type), Ideas (title, note, stage) and Learning Items (title, URL, focused, percent). For uploaded doc files, use Salesforce Files instead of the Supabase storage bucket. The Scratch Pad can be a single record.

Done when

Every table from your inventory has a home in the org.

8 · Move your real data over
WorkingData importCSV

Export each Supabase table to CSV, then load it with Data Loader or sf data import bulk. Load Categories first, then Links, so the lookups can match.

Done when

Your real links, to-dos and deployments show up in list views in the dev org.

02

Write the Apex layer

The server-side code your screens will call.

9 · LinksController
Foundation@AuraEnabledSOQL

An Apex class with a @AuraEnabled(cacheable=true) method that returns Categories with their Links, sorted biggest group first, like the home page does today.

Done when

Calling the method from Anonymous Apex prints your categories and link counts.

10 · TodoController with save + reorder
WorkingDMLBulk updates

Methods to create, update status/priority, toggle focus, and save a new order (update Position on a list of records in one DML call).

Done when

Reordering 20 to-dos is one update, not 20.

11 · Enforce the rules in Apex
WorkingTriggersaddError

Move the page's rules server-side: a trigger that blocks a 4th focused to-do (the 3-focus cap), clears Focused when a to-do is marked Done, and warns when a Deployment moves to Verified with open steps.

Done when

Trying to focus a 4th to-do fails with a clear error, even from the UI or Data Loader.

12 · Test classes
WorkingApex testsCoverage

Tests for every controller and trigger, with test data made inside the test.

Done when

All tests pass and coverage is over 75%, like a real deployment requires.

03

Build the screens in LWC

Rebuild each screen as a Lightning Web Component.

13 · Home grid
WorkingLWC@wire

A libraryHome component that wires to LinksController and renders one section per Category with compact link rows, plus the search box that filters titles and descriptions.

Done when

The Home page of your Lightning App looks like your library's home.

14 · Add and edit links
Workinglightning-record-edit-formToasts

A modal to add or edit a Link, with a Category picker. Show a toast on save and refresh the grid.

Done when

Adding a link shows it immediately in the right section.

15 · To-Do board with drag and drop
StretchEventsImperative Apex

Two columns (To do / Done), drag to reorder and across columns, priority chip, focus toggle. Call TodoController imperatively on drop.

Done when

Dragging a card saves its new position and survives a page refresh.

16 · Deployment Tracker board
StretchComponent compositionGetters

The five-column board with a card component per Deployment: flag checkboxes, the computed “Next:” banner, and the post-deploy checklist.

Done when

Moving a card between columns updates its Stage, and the Next banner changes with the flags.

17 · Scratch Pad autosave
WorkingDebounceImperative Apex

One big text area that saves 1 second after you stop typing, with a “Saving… / All changes saved” status.

Done when

Typing, waiting a second and refreshing keeps your text.

04

Lock it down properly

Real security instead of the site's client-side email gate.

18 · Permission set for the app
WorkingPermission setsFLS

Create Resource_Library_User with access to the objects, fields, Apex classes and the app. Nobody else gets in.

Done when

A test user without the permission set can't see the app or the data.

19 · Private sharing for personal records
StretchOWDSharing

Set the objects to Private so each person only sees their own records, and use with sharing in every controller.

Done when

A second test user with the permission set sees only their own links and to-dos.

05

Stretch goals

Pick these up once the core works.

20 · Share the tracker as a public page
StretchExperience CloudGuest user

Put the Deployment Tracker on an Experience Cloud site so your manager can view it without a Salesforce login, like today's shared tracker link. Make it read-only for guests.

Done when

The site URL shows the board in a private browser window, and guests can't edit.

21 · Pull links from Supabase with a callout
StretchNamed CredentialsHTTP callout

Instead of a one-time CSV load, write Apex that calls the Supabase REST API through a Named Credential and upserts Links by an External ID.

Done when

Running the sync twice doesn't create duplicates.

22 · Deploy from GitHub
StretchCIGitHub Actions

Push the ApexPracticeOrg project to GitHub and add a workflow that runs the tests and deploys on push to main.

Done when

A push to main shows green tests and the change appears in the org.
